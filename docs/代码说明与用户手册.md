## 1.2 技术栈

- Java 17 + Spring Boot 3.5.0 + Spring AI 1.0.0（OpenAI 兼容 starter）
- 接口文档：knife4j 4.5.0（OpenAPI3 Jakarta），启动后访问 `/doc.html`
- 工具库：Lombok（@Data/@Slf4j）、guava
- Python 侧：openai SDK 3.x（Miniconda Python 3.10）
- 大模型：任意 OpenAI 兼容接口（当前使用公司中转站，模型 deepseek-flash）

## 1.3 工程风格约定（对齐 tripod3 规范）

1. 三层 parent：`spring-boot-starter-parent:3.5.0` → `jmn-xxx-parent`（dependencyManagement 集中管版本）→ `jmn-xxx-comm` + `jmn-xxx-main`
2. groupId 统一 `com.jmn`，包名 `com.jmn.<系统>.<业务域>`
3. 配置一律 `.properties`（不用 yml），公共配置 `application.properties`，业务私有配置可扩展 `Global.properties` 模式
4. 打包：主 jar 排除配置文件 + spring-boot repackage(classifier=exec) + maven-assembly 打 tar.gz（conf 外置 + lib 依赖 + bin 启动脚本，`java -classpath conf:lib/*` 启动主类）
5. 返回封装 `RstObj<T>`（state=200 成功/300 警告/500 失败，静态工厂 newOk/newAlert/newError）
6. 业务域分包：`<域>\{web(XxxApi), service, model, vo, tools}`；接口层命名 `XxxApi`（不用 Controller 后缀）
7. `@RequestMapping(value=..., method=...)` 风格；knife4j `@Tag/@Operation` 注解
8. Javadoc 署名 `@author viscen(徐文程) yyyy年MM月dd日`
9. 全局异常处理 `GlobalExceptionHandler`：ServiceAlertException→警告、ServiceErrorException→错误、Exception→500

# 第二部分 jmn-agent（智能体服务）

## 2.1 功能

电力营销领域智能助手"电小二"：
- **多轮对话**：按 sessionId 维护 20 条窗口记忆，同会话支持追问（"那450度电多少钱？"能接住上文）
- **Function Calling**：模型自动决定调用工具，工具结果由模型转述为面向客户的话术
- **SSE 流式**：`/stream` 接口逐字输出
- 内置 3 个模拟工具（真实场景替换为营销系统接口调用即可）：
  - `queryPowerLoad(region, date)` 查询电网负荷
  - `calcPowerBill(usageKwh, customerType)` 阶梯电价试算
  - `queryOutagePlan(region)` 计划停电查询

## 2.3 关键实现说明

**ChatService（核心，约 60 行）**

```java
// 组装：系统提示词 + 工具 + 会话记忆顾问
this.chatMemory = MessageWindowChatMemory.builder().maxMessages(20).build();
this.chatClient = chatClientBuilder
        .defaultSystem(SYSTEM_PROMPT)
        .defaultTools(powerTools)                        // 注册工具对象，扫描 @Tool 方法
        .defaultAdvisors(MessageChatMemoryAdvisor.builder(chatMemory).build())
        .build();

// 调用：按 sessionId 隔离上下文
chatClient.prompt().user(message)
        .advisors(a -> a.param(ChatMemory.CONVERSATION_ID, sessionId))
        .call().content();
```

系统提示词定义了三条行为规则：实时数据必须调工具、工具结果转述成客户话术、超范围问题礼貌拒答。

**PowerTools**：`@Tool(description=...)` + `@ToolParam` 注解方法，返回结构化字符串；用"地区名 hash 生成确定性伪随机数"保证同一地区多次查询结果一致，便于演示与回归。

# 第三部分 jmn-rag（知识库 RAG 问答）

## 3.1 功能

- **入库**：扫描 `data/docs` 下 `.md/.txt` → 段落优先分块（约500字）→ 向量化 → 入库（JSON 持久化，重启免重复向量化）
- **问答**：问题向量化 → 余弦相似度 Top-4 检索 → 拼 Prompt（带 [1][2] 引用编号）→ 模型生成 → 返回答案 + 引用来源
- **向量化双实现可切换**（关键设计）：
  - `local`（默认）：本地字符二元组哈希向量（512维，纯 Java 无外部依赖），**公司中转站未开通 embeddings（503）时全链路照样能跑**
  - `openai`：Spring AI EmbeddingModel 调 OpenAI 兼容 `/embeddings`，接口开通后配置一行切换
- 内置 4 篇电力营销种子文档：电费计算规则、欠费复电业务规则、业扩报装办理指南、有序用电与需求响应政策

## 3.2 代码结构

├── jmn-rag-comm/                            # 公共模块（RstObj/AppConstant/异常，与 agent 同构）
└── jmn-rag-main/
    ├── src/main/java/com/jmn/rag/
    │   ├── RagApplication.java
    │   ├── comm/

## 3.3 关键实现说明

**分块策略（IngestService.chunk）**：按空行切段落 → 单段超长硬切 → 相邻段合并至 chunkSize。每块保留文档名与序号，检索后可溯源。

**向量切换（RagEmbeddingConfig）**：

```java
@Bean @Primary
public EmbeddingClient embeddingClient(@Value("${rag.embedding.mode:local}") String mode, ...) {
    return "openai".equalsIgnoreCase(mode) ? openaiProvider.getObject() : localProvider.getObject();
}
```

**Prompt 模板（RagService）**：要求"仅在参考资料范围内回答 + 末尾标注 [1][2] 引用 + 未收录要明说"，压制幻觉。

## 4.4 已知问题与解决记录（踩坑手册）

| 问题 | 原因 | 解决 |
|---|---|---|
| Java 启动报 no ReactiveWebServerFactory | spring-ai-openai 传入 webflux 依赖，Boot 误判为 Reactive 应用 | CLI 场景加 `spring.main.web-application-type=none`；Web 场景引入 spring-boot-starter-web |
| 直接在 xxx-main 跑 spring-boot:run 报 jmn-xxx-comm 找不到 | comm 未 install 到本地仓库 | 先在父工程 `mvn install`，或用 `mvn -pl jmn-xxx-main -am spring-boot:run` |
| git push 报 Connection was reset | github.com 直连不稳定 | `git config --global http.https://github.com.proxy http://127.0.0.1:10809`（走本机代理）|
| PowerShell 显示 JSON 中文乱码 | PS 默认按非 UTF8 解码 | 用 `curl -o file` 落盘后 `Get-Content -Encoding UTF8` 查看 |
| 中转站 embeddings 503 | 中转站未开通该能力 | jmn-rag 保持 `rag.embedding.mode=local`，开通后切 openai |
| 语雀/WPS 的 docx 兼容性 | WPS 保存的 zip 结构 MS Word 偶发不认 | 用标准 Word/WPS 另存一次 |
